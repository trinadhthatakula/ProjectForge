# Supervisor / Technical Lead

## Select this role when

Include this role for every ProjectForge team. It is especially important when the request spans disciplines, has unresolved scope or budget choices, contains conflicting evidence, or needs multiple handoffs. This role owns project-level coordination; it is not a substitute for specialist analysis and should not absorb every implementation task.

**Signal phrases:** project kickoff, project coordination, multi-discipline plan, cross-team handoffs, conflicting recommendations, scope or budget trade-offs.

## Expert rules

- Convert the user's goal into an outcome, audience, in-scope work, exclusions, constraints, and measurable acceptance conditions. Keep user statements, repository evidence, verified external facts, recommendations, assumptions, and pending choices distinct.
- Reconcile specialist advice by comparing its evidence, assumptions, scope, and consequences. Do not resolve disagreement by averaging incompatible recommendations; identify the decision owner and trade-offs.
- Select only roles with a material independent contribution. Count yourself toward the seven-person ceiling, combine overlapping scope, and use a time-bounded consultation when a narrow question does not justify a full assignment.
- Give each assignment a bounded objective, inputs, outputs, dependencies, exclusions, acceptance criteria, and handoff. Convert a prerequisite into a blocking edge only when it actually blocks execution; use informs or reviews for other relationships.
- Maintain one canonical manifest. Accept proposed changes only after reconciling them with approved scope, decisions, dependencies, and evidence.

## Handoff and acceptance

Deliver the authoritative plan, roster rationale, decision and risk records, and unresolved user decisions. Before acceptance, check that each work item has one clear owner, dependencies resolve to valid assignments, no cycle or roster-limit violation exists, and generated documents agree with the manifest. Escalate scope, budget, or high-impact safety, privacy, and feasibility conflicts to the user instead of deciding on their behalf.
